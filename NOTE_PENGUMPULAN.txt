BAB I: PENDAHULUAN
1.1 Latar Belakang
Bagian administrasi Fakultas Teknologi melayani ratusan permohonan surat administrasi setiap minggunya, seperti Surat Keterangan Aktif Kuliah, Surat Izin Penelitian, dan Surat Pengantar Magang. Proses manual memerlukan kehadiran fisik mahasiswa dan menyulitkan petugas tata usaha dalam memantau siklus hidup surat (baru masuk, sedang diproses, atau selesai). 

1.2 Identifikasi Masalah & Keamanan
Tantangan teknis utama adalah menyediakan sistem berbasis peran (mahasiswa, petugas administrasi, dan kepala bagian) dengan proteksi data yang ketat. Kasus spesifik yang diatasi adalah pencegahan eksploitasi Insecure Direct Object Reference (IDOR), di mana seorang mahasiswa berusaha membuka URL surat mahasiswa lain dengan mengganti ID pada browser.

BAB II: ARSITEKTUR SISTEM & PERANCANGAN
2.1 Tiga Peran Pengguna (Roles):
1. Mahasiswa: Mengajukan surat, melihat riwayat dan memantau status surat miliknya sendiri.
2. Petugas Administrasi: Memeriksa berkas permohonan, menyiapkan draf nomor surat, dan memperbarui status pemrosesan.
3. Kepala Bagian: Mengevaluasi kelayakan dokumen, mengesahkan nomor surat resmi (disetujui), atau menolak permohonan dengan catatan resmi.

BAB III: DETAIL IMPLEMENTASI TEKNIS
3.1 Autentikasi dengan Laravel Breeze
- Menerapkan arsitektur sesi aman Laravel Breeze (Blade Stack).
- Tabel users diperluas dengan kolom: role, nim, prodi, dan no_hp.
- Registrasi publik otomatis menetapkan peran 'mahasiswa' dan memvalidasi NIM unik.

3.2 Middleware Pembatasan Peran (RoleMiddleware)
- Berkas: app/Http/Middleware/RoleMiddleware.php
- Didaftarkan sebagai alias 'role' di bootstrap/app.php.
- Memeriksa apakah auth()->user()->role sesuai dengan parameter rute. Jika tidak sesuai, melempar HTTP 403 Forbidden.

3.3 Pengelompokan Rute (Route Groups)
- Berkas: routes/web.php
- Grup Mahasiswa: prefix('mahasiswa')->middleware(['auth', 'role:mahasiswa'])
- Grup Petugas: prefix('petugas')->middleware(['auth', 'role:petugas'])
- Grup Kepala Bagian: prefix('kepala-bagian')->middleware(['auth', 'role:kepala_bagian'])

3.4 Otorisasi Kepemilikan Data (Data Ownership via SuratPolicy)
- Berkas: app/Policies/SuratPolicy.php
- Logika method view(User $user, Surat $surat):
  Memastikan jika $user adalah mahasiswa, maka $user->id wajib sama dengan $surat->user_id.
- Dipanggil pada controller menggunakan: Gate::authorize('view', $surat).
- Apabila terjadi upaya penggantian ID di URL browser, sistem secara otomatis menolak dengan kode HTTP 403.

BAB V: PEMBAHASAN PERTANYAAN ANALISIS KASUS
5.1 Analisis Pertanyaan 1: Apakah middleware pemeriksaan peran saja cukup untuk mencegah mahasiswa melihat surat milik mahasiswa lain?
Jawaban: TIDAK CUKUP.
Alasan: Middleware peran (Role-Based Access Control) bekerja pada lapisan rute (route-level). Middleware hanya memastikan bahwa pemohon terdaftar sebagai 'mahasiswa'. Karena Mahasiswa A dan Mahasiswa B sama-sama memiliki peran 'mahasiswa', keduanya akan diizinkan melewati middleware untuk rute '/mahasiswa/surat/{id}'. Jika tidak ada validasi kepemilikan data, Mahasiswa A dapat melihat surat Mahasiswa B hanya dengan mengubah ID di browser (kerentanan IDOR). Oleh karena itu, diperlukan lapisan kedua yaitu SuratPolicy / Gate di controller untuk memvalidasi record.user_id === auth()->id().

5.2 Analisis Pertanyaan 2: Bagaimana membedakan pembatasan akses berdasarkan peran dengan pembatasan berdasarkan kepemilikan data?
Jawaban:
- Pembatasan Peran (RBAC): Berfokus pada 'siapa yang boleh melakukan apa' (fitur makro). Contoh: Petugas berhak memproses surat, Mahasiswa tidak boleh. Diterapkan via Route Middleware.
- Pembatasan Kepemilikan Data: Berfokus pada 'siapa yang memiliki baris data tertentu' (objek mikro). Contoh: Mahasiswa A dan B sama-sama boleh melihat surat, tapi hanya data miliknya sendiri. Diterapkan via Laravel Policy / Gate.

5.3 Analisis Pertanyaan 3: Apa risiko jika pemeriksaan hak akses hanya dilakukan di sisi frontend?
Jawaban:
Sangat berbahaya karena melanggar prinsip 'Never Trust Client Input':
1. Pengguna dapat memanipulasi DOM/HTML melalui fitur 'Inspect Element' browser untuk memunculkan tombol yang disembunyikan.
2. Penyerang dapat mengirimkan permintaan HTTP langsung ke server menggunakan cURL atau Postman tanpa melalui antarmuka web.
3. Terjadi kebocoran data pribadi (Data Breach) mahasiswa lain karena backend tidak memfilter akses objek.
4. Terjadi manipulasi status secara ilegal jika endpoint persetujuan tidak diproteksi di sisi server.

BAB VI: KESIMPULAN
Sistem pengajuan surat online Fakultas Teknologi berhasil diimplementasikan menggunakan Laravel 12 dan Laravel Breeze. Dengan memadukan RoleMiddleware pada Route Groups dan SuratPolicy pada level data model, sistem terbukti aman dari upaya manipulasi URL (IDOR) dan menyediakan alur kerja administrasi fakultas yang transparan, efisien, dan andal.
